# 移植说明: basic_framework(F4) → 达妙 DM-MC-Board02(H7)

本文档记录"把 F4 版本的框架整体搬到 MC02 上"的每一个决策和改动点, 便于你对照阅读代码,
也便于以后把新功能从 F4 版本 cherry-pick 过来。

**依据**:

1. 《达妙科技 DM-MC-Board02 电机开发板使用说明书 V1.1》—— 引脚/外设/电源/接口定义;
2. 达妙官方例程 `CtrBoard-H7_ALL`(FreeRTOS + BSP 的完整示例)—— 实际的引脚复用、SPI6/WS2812、
   TIM12 蜂鸣器、FDCAN 初始化方式;
3. `cod-h7-template-main` —— H7 的 FreeRTOSConfig、H7 HAL 工程组织方式;
4. `basic_framework-release-v1.1`(F4) —— 三层框架的接口、风格、应用示例;
5. 你的 CubeMX 工程(`RM.ioc`)—— 已经配置好的 FDCAN/UART/SPI2/TIM3/ADC/USB 引脚与外设。

---

## 1. 总体对照表

| 层次 | F4 版本(F407) | 本工程(H723) | 改动性质 |
| ---- | ---- | ---- | ---- |
| CAN | bxCAN `CAN1/CAN2`, `CAN_HandleTypeDef` | FDCAN `FDCAN1/2/3`, `FDCAN_HandleTypeDef` | **重写** bsp_can, 新增 CANFD 支持 |
| 串口 | USART1/3/6 + DMA 空闲中断 | USART1/2/3、UART5/7、USART10 | 只改句柄/实例数 |
| SPI | SPI1(BMI088) / SPI2(扩展) | SPI2(BMI088), SPI6(WS2812, bsp 内部初始化) | 改句柄 |
| IIC | I2C2/I2C3 | 预留(I2C2 = PB10/PB11), 默认不初始化 | 接口保留 |
| PWM | TIM1/4/5/8/10/11 | TIM1/TIM5/TIM12(bsp 自建) + TIM3(CubeMX, 加热电阻) | 重写时钟/周期计算 |
| ADC | ADC1 无实现(空文件) | ADC1(DMA 循环, 电压) + ADC3(温度) | **新增实现** |
| Flash | F407 混合扇区 + 半字编程 | H723 单 Bank 8×128KB + 32 字节 flash word | **重写** |
| 定时器时基 | TIM14 | TIM2(CubeMX 已配置) | 保持不变 |
| RTOS | FreeRTOS 10.x + CMSIS-RTOS v1(F4 GCC/ARM_CM4F port) | 同一份 FreeRTOS + 同一 port | 只换 `FreeRTOSConfig.h` |
| 数学库 | `libCMSISDSP.a`(CM4) + `arm_math.h` | 无 DSP 库, 用 libm 的 `sinf/cosf` + 自带的 5 个矩阵函数 | 新增 `arm_math_compat.c/h` |
| 日志 | SEGGER RTT | 同一份 SEGGER RTT | 不变 |
| USB | OTG_FS CDC(`CDC_Transmit_FS`) | OTG_HS(FS 模式) CDC(`CDC_Transmit_HS`) | 改函数名 + 回调注入 |

## 3. bsp 层

> 设计目标: **头文件里的接口签名尽量与 F4 版本保持一致**, 让 module 层几乎不用改。

### 3.1 `bsp/bsp_board.h` / `bsp_board.c`(新增)

这是"换板子"的唯一入口, 内容包括:

- 板卡信息、CPU 频率(275MHz);
- `DMA_BUFFER` 宏: 把变量放进链接脚本新增的 `.dma_buffer` 段(AXI SRAM,
  MPU 配置为 Non-Cacheable);
- 所有板载外设的句柄宏: `BOARD_CAN1..3`、`BOARD_USART*`、`BOARD_SPI_IMU`、`BOARD_ADC_*`、
  `BOARD_TIM_IMU_HEATER`、`BOARD_PWM_*`;
- BMI088 片选宏(对应 CubeMX 中 `ACCEL_CS`/`GYRO_CS` 标签);
- **CubeMX 没有配置的外设在这里初始化**: `BoardPWMHardwareInit()` 建 TIM1/TIM5/TIM12,
  `BoardKeyInit()` 配置 PA15, `BoardPower5V/BoardPowerOut()` 控制 PC15/PC14/PC13。

为什么 TIM1/TIM5/TIM12 由 bsp 自己初始化, 而不是写进 `.ioc`?
—— 这样即使用 CubeMX 重新生成代码, 这部分的初始化也不会被覆盖或被改坏; 同时
`BoardPWMGetHandle()` 让 module 层用"板载 PWM 通道号"而不是硬编码定时器。

> 注意: 板载 4 路 PWM 的引脚 PA0/PA2 在 H7 上对应 `TIM5_CH1/CH3`(不是官方例程里的
> TIM2, 因为本工程的 TIM2 被 CubeMX 用作 HAL 时基)。

### 3.2 `bsp/can`(重写, 最重要)

F4 用 bxCAN, 有"邮箱 + 28 个过滤器 + FIFO0/1"的概念; H7 的 FDCAN 是"消息 RAM + RX FIFO +
TX FIFO + 过滤器元素"。本工程的实现选择:

| 项目 | 做法 | 原因 |
| ---- | ---- | ---- |
| 位时序 | `CANRegister()` 第一次在该总线上注册时, 根据 `HAL_RCCEx_GetPeriphCLKFreq(RCC_PERIPHCLK_FDCAN)` **自动计算**预分频/seg1/seg2(采样点 80%), 并用 `HAL_FDCAN_DeInit/Init` 重新配置 | CubeMX 里填的数值不一定与实际时钟匹配; 这样在 `CAN_Init_Config_s` 里直接写 `1000000` 即可 |
| 接收过滤 | **不用过滤器元素**, `HAL_FDCAN_ConfigGlobalFilter()` 接收所有标准帧到 FIFO0, 在中断里按 `(句柄, rx_id)` 分发到实例 | 与 F4 的语义完全一致(注册时指定 rx_id), 也不会因为过滤器数量/消息 RAM 分配而出错 |
| 消息 RAM | 每条总线预留 `0x300` 字(768 word), FDCAN1/2/3 分别是 0/0x300/0x600; 每总线 16 个 64 字节 RX 元素 + 16 个 TX 元素 | H723 共 2560 字, 三条总线够用 |
| 数据长度 | `CANInstance.tx_len` + `CANSetDLC()`(经典帧 ≤8, FD ≤64) | 支持达妙电机的 FD 协议 |
| 帧类型 | `CANSetFrameType(ins, is_fd, brs)`, 默认经典帧 | DJI 电调与达妙 MIT 模式都是经典帧 |
| 发送 | `HAL_FDCAN_AddMessageToTxFifoQ()`, 先等 `HAL_FDCAN_GetTxFifoFreeLevel()`, 超时用 DWT 计时 | 语义与 F4 的 `CANTransmit()` 一致 |
| 错误处理 | `HAL_FDCAN_ErrorStatusCallback()` 遇到 Bus-Off 自动重启总线 | 提高鲁棒性 |

**注意**: 同一条总线上的所有设备必须使用相同的帧类型和波特率(第一个注册的实例决定),
代码里对不一致的情况会打印 warning。

### 3.3 `bsp/usart`

与 F4 相同: `HAL_UARTEx_ReceiveToIdle_DMA()` + 关闭 DMA 半传输中断 + 空闲回调里重启接收。
H7 上的关键改动:

- 实例数从 3 改成 6(`DEVICE_USART_CNT`);
- `recv_buff_size` 从 `uint8_t` 改成 `uint16_t`;
- **实例改用静态池 + `DMA_BUFFER`**, 不再 `malloc`: `malloc` 默认从 DTCM 的 newlib 堆分配,
  而 DTCM 不能被 DMA 访问, 会导致串口 DMA 收不到数据;
- 修复了 F4 版本 `USARTIsReady()` 里 `|` 写成 `&` 的 bug;
- 错误回调里先 `HAL_UART_AbortReceive()` 再重启, 避免 DMA 停在半路。

### 3.4 `bsp/spi` / `bsp/gpio` / `bsp/iic` / `bsp/tools` / `bsp/dwt` / `bsp/log` / `bsp/usb`

- `bsp_spi`: 逻辑不变, 只把实例上限统一成 `SPI_MX_REGISTER_CNT`(F4 版本的数组上限和检查上限不一致);
- `bsp_gpio`: 逻辑不变, 去掉 F4 的寄存器级东西, 纯 HAL;
- `bsp_iic`: 重写成 H7 的 `HAL_I2C_Master_Seq_*` 接口, 回调里按句柄分发;
- `bsp_tools`: 不变(`osSignalSet` + 回调任务);
- `bsp_dwt`: 不变, `DWT_Init(275)`(F4 是 168);
- `bsp_log`: 不变(SEGGER RTT);
- `bsp_usb`: 改成 `CDC_Transmit_HS()`, 并在 `USB_DEVICE/App/usbd_cdc_if.c` 的 **USER CODE 区**
  增加了 `CDCInitRxbufferNcallback()` 与收发回调(与 F4 版本的思路一致, 重新生成代码不会丢)。

### 3.5 `bsp/pwm`(重写关键部分)

- **定时器时钟**: F4 版本用 `APBPrescTable[(RCC->CFGR & RCC_CFGR_PPRE1) ...]` 判断 APB 分频,
  H7 的 RCC 寄存器布局完全不同, 直接抄会算错。这里改成:
  `PCLK == HCLK ? PCLK : 2*PCLK`(APB 分频不为 1 时定时器时钟翻倍), 并对 TIM1/8/15/16/17
  (APB2)与其余(APB1)分别取 PCLK2/PCLK1;
- **周期设置**: 自动选择预分频, 保证 ARR 不超过 16 位(50Hz 舵机、4kHz 蜂鸣器都能用),
  并在改完 PSC/ARR 后写 `EGR = UG` 让其立即生效;
- 占空比接口不变。

### 3.6 `bsp/adc`(新增)

F4 版本的 `bsp_adc.c` 是空文件。这里实现了:

- `BSPADCInit()`: 启动 ADC1 的 DMA 循环采样(CubeMX 已配好 `连续转换 + DMA circular`);
- `ADCGetVbatRaw()/ADCGetVbatVoltage()`: 按分压比换算电池电压(分压电阻在 `bsp_board.h` 中改);
- `ADCGetChipTemperature()`: ADC3 内部温度传感器的阻塞单次转换。

### 3.7 `bsp/flash`(重写)

H7 的 Flash 与 F4 差别很大, 因此接口按 H7 重新设计:

- 扇区: 单 Bank, 8 × 128KB(`FLASH_BANK_1`, sector 0~7);
- 写入单位: 32 字节 flash word(`HAL_FLASH_Program(FLASH_TYPEPROGRAM_FLASHWORD, ...)`);
- 建议把参数放在最后一个扇区(0x080E0000), 避免和代码冲突;
- 接口: `BSPFlashEraseSector()/EraseRange()/Write()/Read()/GetSector()`。

### 3.8 `bsp/ws2812`(新增)

板载 WS2812 接在 **PA7(SPI6_MOSI, AF8)**, 用 SPI 模拟单总线时序:

- SPI6 时钟源选 **HSE(24MHz)**, 4 分频 = 6MHz;
- 1 个 WS 位 = 8 个 SPI 位, `0 → 0x60`, `1 → 0x78`(与达妙官方例程一致);
- 阻塞发送(1 颗灯约 40us), 不使用 DMA, 不会和串口 DMA 抢资源。

## 7. H7 特有的注意事项(踩坑记录)

1. **DTCM 不能被 DMA 访问**
   `0x20000000` 的 DTCM 只连着 CPU 的 D 总线。`.data/.bss` 默认在 DTCM, 所以:
   - 任何 DMA 缓冲区用 `DMA_BUFFER` 宏放到 `.dma_buffer`;
   - 不要用 `malloc()` 出来的缓冲区做 DMA(它在 DTCM 的 newlib 堆里);
   - 本工程已把串口实例、ADC 缓冲区放到 `.dma_buffer`。

2. **D-Cache**
   打开 D-Cache 后, CPU 写入的数据可能还在 cache 里, DMA 读不到。本工程用 MPU 把 DMA 区设为
   Non-Cacheable 来避免这个问题; 若你把缓冲区放到 AXI SRAM 的其它区域, 必须自己调用
   `SCB_CleanDCache_by_Addr()` / `SCB_InvalidateDCache_by_Addr()`。

3. **中断优先级**
   CubeMX 把 FDCAN/UART/SPI/OTG 的中断优先级设为 5, 与 `configMAX_SYSCALL_INTERRUPT_PRIORITY`
   (=5)相等, 这些中断里**可以**调用 `xxxFromISR()` 的 FreeRTOS API, 但不能调用非 ISR 版本。
   TIM2(HAL 时基)优先级 15, 不受影响。

4. **FDCAN 消息 RAM**
   H723 只有 2560 word 的消息 RAM, 三条总线按 `0x300` 间隔分配(见 `CANBusHardwareInit`)。
   如果以后要加过滤器元素或更多 FIFO 元素, 记得同步改 `MessageRAMOffset`。

5. **CANFD 5Mbps 需要 80MHz 的 FDCAN 时钟**
   当前 FDCAN 时钟是 PLL2Q = 96MHz, 能做到 1M/4M(或 1M/2M), **做不到精确的 5Mbps**。
   如果要用达妙电机的 5M 数据段, 把 PLL2 改成 `N=20, Q=3`(VCO=240MHz, /3=80MHz):
   - `Core/Src/main.c` 的 `PeriphCommonClock_Config()`;
   - `RM.ioc` 的 `RCC.DIVN2 / RCC.DIVQ2`。
   这样 80MHz 下 1M(psc 5)和 5M(psc 1)都是整数分频。IMU 加热电阻、蜂鸣器不受影响;
   USART1/USART10 的时钟也来自 PLL2Q, 改成 80MHz 后 921600 仍然可用。

6. **FreeRTOS port**
   用的是 `portable/GCC/ARM_CM4F`。它在 Cortex-M7 上工作正常, 但官方推荐 `ARM_CM7/r0p1`。
   若你有该 port 的源码, 直接替换目录并把 CMake 里的路径改掉即可, 其它代码不用动。

7. **HAL 时基用 TIM2**
   这样 SysTick 完全交给 FreeRTOS。不要同时在 CubeMX 里把 TIM2 配成 PWM/编码器。

## 8. 编译验证结果

移植完成后用 `arm-none-eabi-gcc 15.2.1`(xPack)+ CMake 4.4.4 + Ninja 做了完整编译:

```
默认配置(USE_RM_EXAMPLE=OFF):
  DTCMRAM:  77128 B / 128 KB (58.84%)
  RAM_D1:      32 B / 320 KB (0.01%)   <- .dma_buffer(ADC 缓冲区)
  FLASH:   139052 B / 1 MB  (13.26%)
  text 136808  data 2236  bss 74920

RM 示例配置(USE_RM_EXAMPLE=ON):
  text 162456  data 2584  bss 79248
```

- 两种配置都是 **0 warning / 0 error**;
- 链接结果中确认了 `.dma_buffer` 段位于 `0x24000000`, ADC 缓冲区落在其中;
- `SysTick_Handler / SVC_Handler / PendSV_Handler` 均由 FreeRTOS port 提供,
  与 HAL 的 TIM2 时基不冲突;

## 11. 时钟：为什么是 275MHz，能不能拉到 550MHz

### 11.1 H72x/H73x 的频率上限(数据手册 DS13313 Table 12)

| 时钟 | VOS3 | VOS2 | VOS1 | VOS0 | 说明 |
| --- | --- | --- | --- | --- | --- |
| fCPU (Cortex-M7) | 170 | 300 | 400 | **520**(+CPU_FREQ_BOOST 才 550) | 只有 CPU 能跑这么快 |
| fACLK / fHCLK (AXI/AHB) | 85 | 150 | 200 | **275** | 总线最高就到这 |
| fPCLK (APB) | 42.5 | 75 | 100 | **137.5** | 外设总线 |

两个关键结论：

1. **550MHz 是 CPU 独享的**，总线(AXI/AHB)最高 275MHz，外设总线最高 137.5MHz。
   所以"主频翻倍"≠"整个系统翻倍"。
2. **550MHz 需要 VOS0 + `CPU_FREQ_BOOST` 选项字节**（`SYSCFG->UR18`，是烧进芯片的
   option byte，不是运行时寄存器）。不写这个选项字节，VOS0 下最高只有 520MHz。

### 11.2 本工程现在的配置

```
PLL1: 24MHz / M=2 = 12MHz  →  ×(N=68 + FRACN=6144/8192 = 68.75) = 825MHz VCO
      VCO / P=3 = 275MHz SYSCLK
      D1CPRE=1 → CPU = 275MHz
      HPRE = /1 → HCLK = 275MHz
      APB1/2/3/4 = /2 → 137.5MHz
      VOS0 (必须: 因为 AXI 275MHz > VOS1 的上限 200MHz)
      Flash latency = 3 WS
```

作为对比，**达妙官方例程**是 `PLL1: 12MHz × 40 = 480MHz, P=1 → SYSCLK 480MHz, HPRE=/2 → HCLK 240MHz`，
即"CPU 比总线快一倍"的经典配法。所以 H72x 上 CPU 跑得比总线快是**正常操作**，本工程只是选择了
CPU 与总线同频的简单配法（好处是所有分频都好算）。

### 11.3 拉到 550MHz 需要改什么

| 项目 | 值 |
| --- | --- |
| PLL1 | `M=2, N=45, FRACN=6827, P=1` → VCO 550MHz → SYSCLK **550MHz** |
| D1CPRE | `/1` → CPU 550MHz |
| HPRE | `/2` → AXI/HCLK **275MHz**（不变！） |
| APB1/2/3/4 | `/2` → 137.5MHz（不变！） |
| VOS | VOS0（本来就是） |
| Flash latency | 按参考手册 RM0468 的表（VOS0 + 550MHz）设置 |
| 选项字节 | CubeMX `Project Manager → Option Bytes` 勾 `CPU_FREQ_BOOST`，重新烧录一次 |

**好消息**：因为 HPRE=/2 把 AXI 保持在 275MHz，所以**所有外设的时钟、波特率、定时器分频
都不需要改**（USART1/10 来自 PLL2Q=96MHz，FDCAN 来自 PLL2Q，SPI2 来自 PLL3Q=192MHz，
ADC 来自 CKPER=HSI，APB 仍是 137.5MHz）。真正会变的只有 CPU 相关的两处，已在 11.5 处理。

### 11.4 代价与收益

| 项 | 275MHz | 550MHz | 数据来源 |
| --- | --- | --- | --- |
| 算力 | ~589 DMIPS | ~1177 DMIPS | DS13313: 2.14 DMIPS/MHz |
| 运行电流(全外设开, 25℃) | ~88mA(280MHz VOS2) | ~215mA | DS13313 Table 20 |
| VCORE / 档位 | 1.36V / VOS0 | 1.36V / VOS0 | 电压档不变 |
| 额外功耗 | - | 约 +0.3~0.4W（含 LDO 内部损耗） | 估算 |
| 外设带宽 | 275MHz | **275MHz(不变)** | - |
| Flash 取指 | 受 275MHz 总线限制 | 同样受 275MHz 限制 | 只对 ITCM/DTCM/cache 命中有加速 |

所以：

- **值得拉满的场景**：20kHz 电流环/无感观测器、double 精度的 EKF/矩阵、DCMI 图像处理、
  FFT、多电机 + 高刷新率传感器、或者就是想要余量；
- **不值得的场景**：像本框架这样 1kHz 的任务节拍，CPU 占用是个位数百分比，拉满只是多发热；
- **风险**：`SystemCoreClock`(CPU 时钟) 与 `HAL_RCC_GetHCLKFreq()`(总线时钟) 不再相等，
  任何"写死 275"或"假设两者相等"的代码都会**静默地**把时间算错（不报错，只是定时偏 2 倍）。

### 11.5 已经做好的"时钟无关"改造

为了以后改频率不踩坑，这两处已经从"写死 275"改成运行时读取：

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| `bsp/bsp_init.c` | `DWT_Init(275)` | `DWT_Init(SystemCoreClock/1e6)`（DWT 数的是 CPU 时钟） |
| `bsp/bsp_board.c` | `psc = 275-1` | 由 `HAL_RCC_GetPCLK1Freq()/GetPCLK2Freq()` 推算定时器时钟 |

启动日志也会打印四路实际时钟，改完一眼就能确认：

```
[bsp] DM-MC-Board02 (STM32H723VGT6) init done | SYS=275MHz HCLK=275MHz PCLK1=137MHz CPU=275MHz
```

> FreeRTOS 的 `configCPU_CLOCK_HZ = SystemCoreClock`、HAL 时基 TIM2 的 1MHz 预分频、
> `bsp_pwm` 的定时器时钟计算都是运行时取的，所以都不需要改。
