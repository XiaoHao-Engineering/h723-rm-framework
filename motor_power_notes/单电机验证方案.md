# 单电机能不能验证这套功率控制？

## 结论先说

**能，但只能验证 70%。** 这套工程其实是三件事叠在一起：

| 层 | 内容 | 单电机能不能测 |
|---|---|---|
| ① 电机功率模型 | `Pin = Pm + k1ω² + k2I² + a` 准不准 | ✅ 能，而且必须单电机测 |
| ② 反解 + 选根 | 给定功率解力矩、按方向选根、限幅 | ✅ 能 |
| ③ 四轮分配 + 缓冲/电容 | `k = Pmax/ΣP`、缓冲能量环、电容指令 | ⚠️ 单电机测不了，要用**软件仿真**补 |
| ④ 整车耦合 | 四轮负载不均、走直线、真裁判/真电容 | ❌ 只能上车 |

所以路线是：**单电机台架测 ①②，软件仿真测 ③，最后整车测 ④。** 不要指望一个电机把 ③④ 也测了。

---

## 一、台架怎么搭

```
24V 电源 ── INA226 ── C620 ── M3508 ── 联轴器 ── 负载电机（发电/阻力）
                │                                   │
                └── I2C/串口 ── 主控 ── CAN ─────────┘
```

- **必须有负载**。空转时"力矩电流指令 ≠ 力矩电流"，拟合出来全是错的（报告 5.1 节原话）。
- 负载三种做法，按条件选：
  1. 第二台 M3508 当发电机，接大功率电阻（最好调，能连续跑）；
  2. 磁粉制动器 / 涡流制动器（扭矩可调，贵）；
  3. 飞轮（只能做动态，做不了稳态）。
- 采样：INA226 读母线电流 + 电压，主控 500 Hz~1 kHz 记录 `P、Icmd、given、ω`，格式照抄工程里的 CSV，直接能喂 `fit_power_model.py`。

## 二、三天测试计划

### Day 1：拟合自己的参数

| 工况 | 说明 |
|---|---|
| 正弦扫频 | 力矩指令 0.2~2 Hz、幅值 3000~12000，负载随机变 |
| 斜坡 | 0→12000→0，慢慢加 |
| 恒速变载 | 固定 1000/2000/3000 rpm，负载从小加到堵转边缘 |

跑 `fit_power_model.py`，看三件事：

- `k1 > 0`、`k2 > 0`、RMSE < 1 W；
- 换一组数据交叉验证，RMSE 不爆；
- 用 `k2 ≈ 2.2e-6 × R` 反推相电阻，跟手册对得上。

### Day 2：正向 + 反向

| 测什么 | 怎么做 | 通过标准 |
|---|---|---|
| 正向模型 | 固定 ω，扫 Icmd，比较预测 Pin 与实测 | 误差 < 5%，无系统偏差 |
| 反解 | 固定 ω，给定 P=10/20/40/60 W，看稳态功率 | 稳态误差 < 5% 或 < 2 W |
| 选根方向 | 给负力矩、低转速，看是否真的在制动 | 力矩方向不反、功率不跳变 |
| 限幅 | 低速大功率，看是否停在 16000 | 不超调、不发散 |
| 无解分支 | 目标功率低于损耗地板 | 不出现"放行原力矩"导致的超功率 |

### Day 3：闭环 + 模拟裁判

用软件模拟缓冲能量和电容（见下节），把 `chassis_power_control` 的核心逻辑接上，看：

- 预算 20 W 时，电机功率是否稳在 20 W 附近；
- 突然把预算改成 40 W，响应是否平顺、不震荡；
- 缓冲能量是否稳定在 30 J。

## 三、没有裁判/电容怎么办：软件仿真

### 1. 裁判系统模型（缓冲能量）

裁判的本质是一个积分器：

```
E += (Pmax - P_battery) * dt;      // 超了扣，少了充
E = clamp(E, 0, 60);
```

- `P_battery`：实测的电池侧功率（INA226）；
- 当 `E == 0` 时，把 `Pmax` 强制降到惩罚值（模拟裁判限功率）。

把它接到 `buffer_pid` 上，就等价于接了一个真裁判——只是这个"裁判"是你自己写的，方便注入各种工况。

### 2. 超级电容模型

```
E_cap += (P_battery - P_motors) * dt;
E_cap = clamp(E_cap, 0, E_cap_max);
P_cap = (P_motors - P_battery);          // 正=放电，负=充电
```

台架上可以用**带电流限制的直流电源**模拟电池（限制 45 W），电机要更多时，电源电压会被拉低——这本身就是电容放电的物理近似。要更真，就在电源和电调之间并一组真电容。

### 3. 四轮虚拟化

单电机也能验证"分配算法"，不用四个电机：把同一组实测数据复制四份，给四个不同的 ω 和 Icmd（比如 780/800/810/820 rpm），跑一遍分配逻辑，检查：

- `k` 是否等于 `预算 / ΣP`；
- 四轮目标功率之和是否等于预算；
- 负功率电机是否被跳过；
- 反解出来的电流是否都在 ±16384 内。

这验证的是**代码逻辑**，不是物理，但足够把 bug 挡在装车之前。

## 四、判定标准（通过/不通过）

| 项 | 通过 | 不通过的表现 |
|---|---|---|
| 模型残差 | RMSE < 1 W，无偏 | 残差随转速单调漂 → 激励不足/电压没记 |
| 反解精度 | 稳态误差 < 5% | 总是低 10% → 系数挂错（比如 k1/k2 反了） |
| 选根 | 方向一致、连续 | 一给负力矩就抖 → 选错根 |
| 限幅 | 平滑饱和 | 饱和后震荡 → PID 积分没处理 |
| 缓冲环 | E 稳定在 30±5 J | 一路掉到 0 → 方向反了（正反馈） |

## 五、常见坑

1. **空转拟合**：最常见，拟出来的 k1 是负的。
2. **电源限流**：电源自己限流会把电压拉低，看起来像"模型不准"，其实是供电不够。
3. **温度**：连续跑 10 分钟，绕组升温 40°C，R 变大，k2 漂 10%。
4. **母线电压没记**：电池从 25.2 掉到 22 V，功率差 10%，拟合全歪。
5. **只测一个转速**：ω² 和 I² 共线，参数不可信（见工程里 `constantspeed.csv` 的 5.5e-6）。

## 六、一句话

**单电机负责"这套模型准不准"，软件仿真负责"这套逻辑对不对"，整车负责"合起来行不行"。** 三步都做完，再上赛场。
